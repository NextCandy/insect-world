# 首屏加载实验与 WebGL 探测修复

## 本轮交付

- 探测只接受 WebGL 2。项目使用 Three.js r171；已安装源码 `node_modules/three/src/renderers/WebGLRenderer.js` 明确说明自 r163 起不支持 WebGL 1，构造器也仅请求 `webgl2`。此前把 WebGL 1 当作可用，会继续尝试不支持的渲染器。
- 探测成功后通过可选的 `WEBGL_lose_context` 扩展释放新建临时 canvas 的上下文。扩展缺失或抛错不改变可用性判断；实际显示 canvas 不参与探测释放。
- 补充 WebGL 1-only、探测上下文释放、可选扩展失败和创建上下文失败的单测。浏览器回归检查探测释放被实际调用、显示上下文仍有效，以及 WebGL 1-only 时显示剪影、正文可读且不请求首物种模型构建模块。

## 未采用的 Canvas 分包实验

以 `768ebda` 为基线，在同一台机器、同一预览服务和 Chromium 软件渲染环境中，每组运行三个冷上下文。手机条件为英文首页、4G 网络模拟、CPU 四倍减速；以下为三个样本的中位数，单位毫秒。

| 方案 | 桌面首帧 | 手机首帧 | 手机占位内容出现 |
| --- | ---: | ---: | ---: |
| 基线 | 998 | 3031 | 1390 |
| 延迟加载 Canvas | 1260 | 7327 | 990 |
| Canvas 并行预加载 | 1632 | 3531 | 915 |

延迟加载实验将公共入口压缩体积从约 297 KiB 降到约 51 KiB，但渲染依赖仍需下载；正文提前出现，首个 3D 帧却变慢。并行预加载也没有显示首帧改善。因此两版实验均已撤回，原有静态 Canvas 导入和首物种预热保持原样。测试中为异步 Canvas 修改的组件断言也已还原。

软件渲染、少量样本和帧耗时波动限制了这些数字的外推范围；它们用于拒绝当前方案，不能视为真实手机的性能预测。本轮 WebGL 修复不宣称首帧提速，也不宣称兜底时不下载 Three.js。

原始实验 JSON 在本地忽略目录 `audit-out/2026-10-01/canvas-{before,after,parallel}-{desktop,mobile}.json`，以上表格保留了决策所需的可复核记录。
