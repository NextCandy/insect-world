# 反馈重试去重

## 问题与处理

15 秒等待超时只能说明浏览器未收到确认，不能证明服务端未写入。原客户端重试会再次插入留言，消耗每日五条额度。本轮为每份尚未确认的草稿生成随机 UUID v4；网络失败、无效收件响应和超时后的未改草稿重试沿用该标识。

数据库新增可空 `request_id` 和唯一索引。限额判断仍和插入位于同一 SQL，使用 `ON CONFLICT(request_id) DO NOTHING` 原子去重；没有新增“先查询再写入”的竞争窗口。写入零行时，再检查该标识对应的既有内容：相同的归一化正文、邮箱、语言、意图、物种和部位返回成功，否则返回 409。已有收件的重试即使每日限额已满也可确认，不再次计数。

标识对应单次提交，不是访客身份；重试确认不要求相同 IP 或 UTC 日期。旧客户端省略标识时仍受原有五条限额约束。已有留言、收件状态与其它数据保持原样。

实现依据：[SQLite UPSERT](https://www.sqlite.org/lang_upsert.html) 对唯一约束冲突提供 `DO NOTHING`，避免再次插入。

## 客户端边界

- 标识仅存在当前表单 hook 的内存中，不存储正文或邮箱到浏览器持久存储。
- 内容、邮箱、意图、物种、部位或语言改变后，下次提交使用新标识。成功确认后再提交相同内容也视作新意图。
- 关闭表单或刷新页面会丢失现有草稿和标识。关闭后手动重写、编辑后提交，以及旧客户端无标识请求，不属于本轮去重保证。
- HTTP 409 映射到现有表单校验错误；失败保留草稿。

## 数据库部署顺序

新库直接执行完整 `db/schema.sql`。旧库先执行 `PRAGMA table_info(messages)`；仅在没有 `request_id` 列时执行一次 `db/migrations/2026-10-01-feedback-request-id.sql`，之后再部署端点。该增量文件不是可重复执行的初始化脚本；不能对已迁移或由新 schema 创建的库再次运行。

此次分别核对生产库 `insect-world` 与隔离预览库 `insect-world-preview`。先迁移并在预览环境验证实际 API，再迁移生产库和发布。迁移只新增空列和唯一索引，不回填、更新或删除已有留言。旧版本端点忽略新增列，发布窗口内仍可正常收件；回滚应用也可保留这两个新增结构。

Cloudflare 提供[版本化 D1 migrations](https://developers.cloudflare.com/d1/reference/migrations/)；本仓库当前沿用显式 `d1 execute --file` 流程，本轮没有擅自初始化迁移历史表。

## 验证范围

真实 SQLite 端点测试覆盖同标识 20 个并发重试、满额重试、不同内容并发冲突、六个事实字段的冲突、非法标识、跨日与网络变化、旧客户端并发限额，以及迁移后已有留言保留。

组件测试覆盖超时和响应丢失后的标识保留、编辑和切换语言、成功后新意图。真实 Chromium 表单回归先返回 HTML 假收件、再重试确认，核对请求标识一致和草稿保留；“再说一条”后相同正文获得新标识。该回归拦截 API，不向生产收件箱写测试内容。

本地全量 131 个文件、5,600 项测试与 18 个浏览器场景通过，类型检查和生产构建通过。独立只读审核未发现必须修复的问题。

隔离预览部署 `ba6e072a` 的实际端点：20 个并发请求全部返回 200/ok，相同标识不同正文返回 409，再次原样重试返回 200；远程预览库按该标识查询实际只有 1 行。测试后只删除该随机标识对应的测试留言。预览部署刚完成时出现过 HTML 响应，端点随后就绪；验证重试复用了原标识，未以 HTTP 200 本身判定收件。

## 后续可实施项

1. 内容核校：当前只有首物种的部分断言有明确来源，继续逐物种核对中英文事实与课程；不能把结构测试通过视为科学事实正确。
2. 真实手机性能：当前首帧记录来自软件渲染，需真实设备测量才能决定渲染和资源策略；已否决的 Canvas 分包不重新当作已完成优化。
3. 草稿恢复：只有真实需求明确后再考虑跨关闭/刷新恢复；届时需同时设计正文隐私、持久化失败和标识生命周期。
