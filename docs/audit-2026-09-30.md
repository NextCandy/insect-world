# 项目审核与优化 · 2026-09-30

本轮审核基于 `96d371c`，已 fetch 并确认本地与 `origin/master` 一致，初始工作区干净。检查了应用交互、响应式布局、模型加载和缓存、反馈接口、语言分流、安全响应头、依赖与 CI，并实际加载桌面中文页和手机英文页。

项目的优势是模型按物种动态加载、中英数据契约、WebGL 降级、照片许可与署名清单，以及数量充足的几何和交互测试。主要改进方向是把已有测试未覆盖的浏览器故障、接口并发和布局问题纳入验证。

## 已发现并实施

| 优先级 | 发现与复现 | 实施 |
| --- | --- | --- |
| P1 | `App` 的主题读取/写入和 `LanguageHint` 直接访问 localStorage；浏览器禁用存储时页面白屏，写入失败还会阻止关闭语言提示 | 捕获存储访问和读写异常；主题切换、提示条关闭仍在当前会话内生效 |
| P1 | 反馈接口先查询每日提交数再写入；带异步读取延迟的真实 SQLite 测试中，20 个并发请求全部被接受 | 改为一条 `INSERT … SELECT … WHERE COUNT < limit`，根据实际写入行数返回成功或 429；同组并发仅接受 5 条，无需数据库迁移 |
| P2 | “换一只看看”使用 `(5 × index + 3) % 63`，第 16 个物种中华虎甲点击后仍是自己，且无法均匀探索其它物种 | 在 `1..n−1` 中随机取偏移，保证换到其它物种；覆盖随机数边界和原固定点 |
| P2 | 语言分流实际依赖 Cookie、User-Agent、Accept-Language，但响应仅声明语言，并覆盖静态管线原有 Vary | 两种响应均返回 `private, no-store`，补齐 Vary 并保留既有项；明确语言选择不会被共享缓存串给其它访客 |
| P2 | 390px 英文首屏中，生活史按钮从 x≈212 开始，而物种名延伸至 x≈245，发生重叠 | ≤640px 入口收为 44×44 的播放按钮，保留可访问名称和 tooltip，限制身份区子项宽度 |
| P2 | npm audit 报告 3 项开发依赖问题：Vitest、@vitest/mocker 和 nanoid | Vitest 固定为修复版 4.1.11，nanoid 更新至 3.3.18；当前 audit 为 0 |

依赖问题影响开发工具，不等于公开的静态站已可被利用。版本与影响范围参考 [Vitest 公告](https://github.com/advisories/GHSA-82fw-gwwq-j7x9) 和 [nanoid 公告](https://github.com/advisories/GHSA-2v37-7h3g-55p8)。采用仍兼容 Vite 6 的 Vitest 修复版，未同时升级 React/Three.js。

新增反馈端点测试直接执行端点生成的 SQL，异步读取模拟 D1 网络往返，避免预设 mock 返回值掩盖竞争窗口。Node 内置 SQLite 需要较新的 Node，已在 engines 和双语 README 中明确要求 Node ≥22.13，CI 继续使用 Node 22。

新增 `npm run test:browser`，自动启动并关闭本地产物预览服务，检查中英文页面及较长英文名称在 320/390/640px 的身份区、横向溢出与触控区域；还检查中华虎甲换虫和两种存储禁用方式。浏览器测试拦截正式统计请求，避免产生测试流量；第三方统计脚本不属于这些场景的验证范围。CI 已接入 Chromium 安装与浏览器检查。

README 同时修正了“无后端”的描述：页面静态托管，语言分流和反馈提交由 Pages Functions 承担，反馈写入 D1。

## 后续优化建议

1. **P1：为科普内容建立来源与核校状态。** 数据结构测试无法证明生活史、地理分布、数值和冷知识正确。建议从访问量高的物种开始，为关键事实附来源和核校日期；未经核校的内容继续明确标注。此次未声称已完成 63 种昆虫的专业核校。
2. **P2：限制反馈请求体与等待时间。** 服务端目前完整解析 JSON 后才校验 500 字正文，客户端 fetch 也无等待超时。建议用流式字节上限和明确的提交超时保护异常请求；保留用户正文以便重试。
3. **P2：先测首屏分段，再决定代码分割。** 公共块包含 Three.js 等渲染依赖；仅改 chunk 切分未必减少首屏下载总量。建议沿用 `?perf=1` 比较中英文、冷/热缓存、手机首帧及脚本求值成本，再决定是否延迟加载渲染入口或次要浮层。
4. **P2：补长期浏览的显存测量。** 成虫已有 LRU，阶段模型缓存没有容量上限，预取还会构建几何。建议实测连续浏览多个生活史后的 GPU 资源、帧耗时及手机发热，再考虑阶段缓存逐出与预取策略。
